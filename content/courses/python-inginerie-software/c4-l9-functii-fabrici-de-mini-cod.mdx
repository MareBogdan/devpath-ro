# Funcții: Fabrici de mini-cod

## CONTEXT

Conceptul de subrutină/funcție apărea deja în primele limbaje de asamblare din anii '50, ca răspuns direct la nevoia de a reutiliza cod fără a-l retranscrie manual de fiecare dată — una dintre cele mai vechi idei fundamentale din istoria programării, alături de bucle și condiții.

Python tratează funcțiile ca **cetățeni de primă clasă** (first-class citizens) — o funcție poate fi atribuită unei variabile, transmisă ca argument altei funcții, returnată dintr-o altă funcție, exact ca orice altă valoare (`int`, `str`, listă). Această flexibilitate stă la baza unor pattern-uri avansate pe care le vei întâlni în L20 (decoratori) și e fundamentul întregii programări funcționale disponibile în Python — spre deosebire de limbaje mai vechi (C clasic), unde funcțiile nu pot fi manipulate ca valori la fel de liber.

## MIEZUL

### Anatomia unei funcții

```python
def calculeaza_tva(pret, cota=0.19):
    """Calculează TVA-ul pentru un preț dat, cu o cotă implicită de 19%."""
    return pret * cota

rezultat = calculeaza_tva(100)          # folosește cota implicită: 19.0
rezultat2 = calculeaza_tva(100, 0.09)    # cotă specificată explicit: 9.0
```

`def` declară o funcție nouă. `pret` — **parametru obligatoriu**, trebuie furnizat la fiecare apel. `cota=0.19` — **parametru cu valoare implicită (default)**, opțional la apel; dacă nu-l specifici, se folosește `0.19` automat. `return` oprește execuția funcției imediat și trimite valoarea înapoi apelantului — o funcție fără `return` explicit returnează implicit `None`.

<CosmoHint emotion="thinking">
De ce ordinea parametrilor cu valori implicite contează strict? Python impune o regulă: toți parametrii obligatorii trebuie să vină ÎNAINTE de cei cu valoare implicită în definiție — `def f(a, b=1, c=2):` e valid, `def f(a=1, b, c):` aruncă `SyntaxError`. Motivul e mecanic: la apel, Python trebuie să poată determina neambiguu ce argumente poziționale corespund căror parametri, iar parametrii opționali plasați la mijloc ar face asta imposibil de dedus fără informație suplimentară.
</CosmoHint>

### Argumente poziționale vs. cu nume (keyword)

```python
def creeaza_utilizator(nume, varsta, oras="București"):
    return {"nume": nume, "varsta": varsta, "oras": oras}

creeaza_utilizator("Ana", 25)                          # poziționale
creeaza_utilizator(nume="Ana", varsta=25, oras="Cluj")   # cu nume (keyword)
creeaza_utilizator("Ana", oras="Cluj", varsta=25)         # mixt — nume oricând, poziționale în ordine
```

Argumentele **cu nume** (keyword arguments) sunt esențiale pentru lizibilitate când o funcție are mulți parametri, mai ales booleeni sau numerici, unde ordinea poziționala e ambiguă pentru cititor: `antreneaza_model(epoci=10, rata_invatare=0.001, verbose=True)` comunică instant ce reprezintă fiecare valoare, spre deosebire de `antreneaza_model(10, 0.001, True)`, unde niciun argument nu-și explică sensul fără să consulți definiția funcției.

### `*args` și `**kwargs` — număr variabil de argumente

```python
def suma_tot(*numere):          # colectează argumentele poziționale extra într-un tuple
    return sum(numere)

suma_tot(1, 2, 3)                # 6
suma_tot(1, 2, 3, 4, 5)          # 15 — funcționează cu oricâte argumente

def afiseaza_info(**detalii):    # colectează argumentele cu nume extra într-un dicționar
    for cheie, valoare in detalii.items():
        print(f"{cheie}: {valoare}")

afiseaza_info(nume="Ana", varsta=25, oras="Iași")
```

`*args` (numele "args" e convenție, nu obligatoriu — semnul `*` face treaba) colectează orice numere de argumente poziționale suplimentare într-un tuple. `**kwargs` colectează orice argumente cu nume suplimentare într-un dicționar. Ambele apar constant în semnăturile de funcții din biblioteci reale de AI — un wrapper generic peste un model poate accepta `def apeleaza_model(prompt, **parametri_model):`, transmițând transparent orice parametru specific modelului (`temperature`, `max_tokens`) fără ca funcția wrapper să-i cunoască pe toți explicit.

{/* TABLE */}

| Sintaxă | Colectează | Tip rezultat |
|---|---|---|
| `def f(a, b):` | Parametri fixați, obligatorii | — |
| `def f(a, b=1):` | Parametru cu valoare implicită | — |
| `def f(*args):` | Argumente poziționale extra | `tuple` |
| `def f(**kwargs):` | Argumente cu nume extra | `dict` |
| `def f(a, *args, **kwargs):` | Combinație — cel mai flexibil | mixt |

### Type hints — adnotări opționale de tip

Din L1, ai văzut că Python nu cere declarații explicite de tip. **Type hints** (introduse în Python 3.5, extinse constant de atunci) oferă un compromis: adnotezi opțional tipurile, fără să schimbi execuția — Python ignoră complet aceste adnotări la runtime, dar unelte externe (mypy, Pylance, IDE-uri) le folosesc pentru a detecta erori de tip *înainte* de rulare:

```python
def calculeaza_tva(pret: float, cota: float = 0.19) -> float:
    return pret * cota
```

`pret: float` — adnotare de tip parametru. `-> float` — adnotare de tip returnat. Deși pur informative pentru interpretor, type hints sunt aproape universale în cod Python profesional modern, inclusiv în majoritatea bibliotecilor AI (PyTorch, FastAPI, Pydantic — vei vedea Pydantic în detaliu în L24 — se bazează masiv pe type hints pentru validare automată).

<CosmoHint emotion="encouraging">
`help(functie)` afișează docstring-ul unei funcții direct în terminal sau REPL — util instant pentru a înțelege ce face o funcție necunoscută dintr-o bibliotecă, fără să cauți documentația online. Funcțiile bine scrise din biblioteci serioase (NumPy, PyTorch) au docstring-uri extinse, accesibile exact așa, chiar și offline.
</CosmoHint>

### Funcții ca valori — trecerea unei funcții ca argument

```python
def aplica_transformare(lista, transformare):
    return [transformare(x) for x in lista]

numere = [1, 2, 3, 4]
patrate = aplica_transformare(numere, lambda x: x ** 2)   # [1, 4, 9, 16]

def dublu(x):
    return x * 2

dublate = aplica_transformare(numere, dublu)               # [2, 4, 6, 8]
```

`lambda` creează o funcție anonimă, de o singură expresie, fără nume — utilă pentru funcții mici, folosite o singură dată, ca argument al altei funcții. Echivalentul: `lambda x: x ** 2` e identic funcțional cu `def patrat(x): return x ** 2`, doar mai concis pentru cazuri simple.

Acest pattern — trecerea unei funcții ca argument altei funcții — e omniprezent în framework-urile AI/ML: funcțiile de optimizare (`optimizer.step`), funcțiile de callback la finalul fiecărei epoci de antrenare, funcțiile de activare — toate sunt, la bază, funcții transmise ca parametri altor funcții care le apelează la momentul potrivit.

### Funcții pure vs. cu efecte secundare

O **funcție pură** produce mereu același rezultat pentru aceleași argumente și nu modifică nimic în afara ei (nu scrie fișiere, nu modifică variabile globale, nu face cereri de rețea). O funcție cu **efecte secundare** face exact asta — modifică stare externă, salvează în bază de date, printează. Ambele sunt necesare într-un program real, dar funcțiile pure sunt mult mai ușor de testat, de raționat despre, și de reutilizat în siguranță — o distincție care va deveni centrală când discutăm scope-ul variabilelor în lecția următoare.

### Funcții anonime cu `lambda` — sintaxa completă

L9 a introdus deja `lambda` în trecere, dar merită revizitată direct, alături de restul sintaxei de funcții, pentru claritate completă:

```python
patrat = lambda x: x ** 2
adunare = lambda a, b: a + b

print(patrat(5))       # 25
print(adunare(3, 4))     # 7
```

O `lambda` e echivalentă funcțional cu un `def` obișnuit, dar restricționată la **o singură expresie** — fără `if`/`elif` explicit (doar ternar), fără bucle, fără mai multe instrucțiuni. Convenția Python (PEP 8) recomandă explicit să nu atribui o `lambda` unui nume separat, ca în exemplul de mai sus — dacă are nevoie de un nume, un `def` obișnuit e considerat mai clar și mai ușor de depanat (are `__name__` propriu, poate avea docstring); `lambda` e rezervată pentru cazuri unde o funcție e transmisă direct ca argument, fără să merite propriul nume.

```python
numere = [(1, "b"), (3, "a"), (2, "c")]
numere_sortate = sorted(numere, key=lambda pereche: pereche[1])   # sortează după al doilea element
print(numere_sortate)   # [(3, 'a'), (1, 'b'), (2, 'c')]
```

Acest pattern — `lambda` ca argument `key=` pentru `sorted()`, `max()`, `min()`, `filter()` — e cazul de uz canonic, unde funcția anonimă e folosită o singură dată, exact în acel punct, fără nevoia unui nume separat undeva mai sus în cod.

### Recursivitatea — o funcție care se apelează pe sine

O funcție poate apela ea însăși, direct, din propriul corp — pattern-ul numit recursivitate, util pentru probleme care se descompun natural în sub-probleme identice, mai mici:

```python
def factorial(n):
    if n <= 1:              # caz de bază — oprește recursivitatea
        return 1
    return n * factorial(n - 1)   # apel recursiv, cu argument redus

print(factorial(5))   # 5 * 4 * 3 * 2 * 1 = 120
```

Fiecare funcție recursivă corectă are obligatoriu un **caz de bază** (condiția care oprește recursivitatea, aici `n <= 1`) și un **pas recursiv** care se apropie garantat de acel caz de bază la fiecare apel (aici, `n - 1`, mereu mai mic). Omiterea cazului de bază, sau un pas recursiv care nu se apropie de el, produce exact `RecursionError`-ul menționat deja în L8 — echivalentul recursiv al buclei infinite.

Deși elegantă pentru probleme naturale recursive (parcurgerea unei structuri arborescente, de exemplu structura de directoare a unui sistem de fișiere), recursivitatea nu e implicit "mai rapidă" sau "mai eficientă" decât o buclă echivalentă — de multe ori e mai lentă, din cauza overhead-ului fiecărui apel de funcție nou (crearea unui nou cadru de stivă, discutat în cursul de Sisteme de Operare). Alegerea între recursivitate și o buclă explicită rămâne, în primul rând, o decizie de lizibilitate, nu de performanță garantată.

### Funcții de nivel de modul vs. funcții imbricate

```python
def functie_exterioara():
    def functie_interioara():          # definită ÎN INTERIORUL alteia — vizibilă doar acolo
        return "rezultat intern"
    return functie_interioara()

print(functie_exterioara())   # "rezultat intern"
print(functie_interioara())      # NameError — nu există în afara funcției exterioare
```

O funcție definită în interiorul alteia (funcție imbricată) e vizibilă *doar* în scope-ul funcției care o conține — exact regula LEGB pe care o vei detalia complet în lecția următoare. Acest pattern devine esențial pentru decoratori (L20) și closures — funcții care "țin minte" starea din funcția care le-a creat, chiar după ce aceasta s-a terminat de executat.

De ce funcțiile pure sunt preferate explicit în cod de testare automată (unit tests)? Pentru că un test al unei funcții pure verifică o singură relație, complet izolată — "pentru input X, aștept output Y" — fără nicio grijă despre starea globală, fișiere, sau rețea. O funcție cu efecte secundare cere fie mock-uri (simulări ale dependențelor externe), fie o bază de date de test separată, complicând semnificativ scrierea și întreținerea testelor. Extrage cât mai multă logică posibil în funcții pure, izolate, și limitează efectele secundare la un strat cât mai mic, la marginea programului — un principiu de design repetat constant în cod profesional.

## REVEAL

{/* TABLE */}

| Componentă | Rol |
|---|---|
| `def nume(...):` | Declară funcția |
| Parametri obligatorii | Trebuie furnizați la apel |
| Parametri cu valoare implicită | Opționali, folosesc valoarea implicită dacă nu sunt specificați |
| `return valoare` | Trimite rezultatul înapoi apelantului |
| `*args` / `**kwargs` | Colectează argumente extra, poziționale/cu nume |
| Type hints (`param: tip`) | Documentare + verificare externă, ignorate la runtime |

<FactBox>
**Funcții în cifre:**
- Funcțiile sunt "first-class citizens" în Python — pot fi atribuite, transmise, returnate ca orice altă valoare
- Type hints: introduse formal în **Python 3.5** (2015), extinse constant în versiunile ulterioare
- `lambda`: limitat la o singură expresie — pentru logică mai complexă, `def` obișnuit e obligatoriu
- O funcție fără `return` explicit: returnează implicit `None`
- Regula de ordine a parametrilor: obligatorii înainte de cei cu valoare implicită, mereu
- `*args`/`**kwargs`: pattern-uri prezente în semnăturile a aproape oricărei biblioteci Python majore
</FactBox>

## ÎNCHEIERE

Funcțiile transformă cod repetitiv într-o unitate reutilizabilă, testabilă, apelabilă din oriunde ai nevoie de acea logică — schimbarea comportamentului într-un singur loc se propagă automat la toate apelurile. Parametrii cu valoare implicită, `*args`/`**kwargs`, și type hints extind flexibilitatea acestei unități de bază fără să compromită claritatea, dacă sunt folosite cu disciplină.

Dar unde "trăiește" o variabilă definită în interiorul unei funcții? Poate o funcție să vadă și să modifice variabile definite în afara ei? Lecția următoare răspunde precis la aceste întrebări — conceptul de scope, local vs. global.
