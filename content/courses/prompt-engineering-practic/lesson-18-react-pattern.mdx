# ReAct Pattern: Raționament + Acțiune

Tehnicile de prompting pe care le-am explorat până acum îmbunătățesc raționamentul modelului în cadrul unui singur apel. **ReAct** (Reasoning + Acting) introduce un concept diferit: modelul alternează între gândire și acțiuni în lumea externă.

## Ce este ReAct?

ReAct este un framework de prompting care structurează procesul de rezolvare a problemelor în cicluri repetate de:

1. **Thought (Gând)**: modelul raționează despre situația curentă
2. **Action (Acțiune)**: modelul decide ce acțiune să execute (căutare web, calcul, apel API)
3. **Observation (Observație)**: modelul primește rezultatul acțiunii
4. Ciclul se repetă până la răspunsul final

Aceasta este structura de bază a agenților AI moderni.

## Exemplu simplificat în text

    Prompt: Câte zile sunt de la nașterea lui Eminescu până azi?

    Thought: Trebuie să știu data nașterii lui Eminescu și data de azi.
    Action: Caut data nașterii lui Eminescu
    Observation: Mihai Eminescu s-a născut la 15 ianuarie 1850.

    Thought: Am data nașterii. Trebuie să calculez diferența în zile.
    Action: Calculez numărul de zile între 15 ianuarie 1850 și data curentă
    Observation: [calcul: X zile]

    Thought: Am ambele informații necesare pentru răspunsul final.
    Final Answer: De la nașterea lui Eminescu (15 ianuarie 1850) au trecut X zile.

## ReAct cu unelte reale (Tool Use)

Puterea reală a ReAct apare când modelul are acces la unelte reale:

- **Căutare web** (Bing API, Brave Search API)
- **Calculator** (execuție Python)
- **Baze de date** (SQL queries)
- **API-uri externe** (vreme, prețuri, etc.)
- **Sistem de fișiere** (citire/scriere documente)

Exemplu de configurare cu Vercel AI SDK:

    import { openai } from '@ai-sdk/openai';
    import { generateText, tool } from 'ai';
    import { z } from 'zod';

    const result = await generateText({
      model: openai('gpt-4o'),
      tools: {
        getWeather: tool({
          description: 'Obține vremea curentă pentru un oraș',
          parameters: z.object({ city: z.string() }),
          execute: async ({ city }) => {
            const response = await fetch("/api/weather?city=" + city);
            return response.json();
          }
        }),
      },
      prompt: 'Care este temperatura în București acum?'
    });

Modelul va decide automat când să apeleze uneltele și ce argumente să folosească.

## Structura detaliată a unui ciclu ReAct

    === ITERAȚIA 1 ===
    Thought: Utilizatorul întreabă despre prețul acțiunilor Apple.
             Trebuie să verific prețul curent.
    Action: get_stock_price(symbol="AAPL")
    Observation: {"symbol": "AAPL", "price": 189.43, "change": "+2.1%"}

    === ITERAȚIA 2 ===
    Thought: Am prețul curent. Ar fi util să verific și trendul pe 7 zile.
    Action: get_stock_history(symbol="AAPL", days=7)
    Observation: {"avg_7d": 185.20, "trend": "crescător"}

    === FINAL ===
    Thought: Am toate informațiile pentru un răspuns complet.
    Final Answer: Acțiunile Apple (AAPL) sunt la 189.43 USD, în creștere cu 2.1%
    față de media din ultimele 7 zile (185.20 USD).

## Diferența față de Chain-of-Thought simplu

| Aspect | Chain-of-Thought | ReAct |
|--------|------------------|-------|
| Cunoaștere | Statică (din training) | Dinamică (din lume) |
| Acțiuni | Niciuna | Apeluri de unelte |
| Actualizare | Nu | Da (observații în timp real) |
| Use case | Raționament intern | Interacțiune cu sisteme externe |

## Gestionarea erorilor în ReAct

Modelele bune de ReAct gestionează erorile de la unelte:

    Action: search_database(query="produsul X")
    Observation: ERROR: Produsul nu a fost găsit în baza de date.

    Thought: Căutarea directă a eșuat. Voi încerca o căutare mai generică
             sau voi informa utilizatorul că produsul nu există.
    Action: search_database(query="produse similare cu X")

## Limitele ReAct

**Latența**: fiecare iterație = un apel API. Mai multe iterații = mai mult timp.

**Costul**: mai mulți tokeni pentru thought-uri și observații.

**Bucle infinite**: modelul poate intra în bucle dacă nu primește observații satisfăcătoare. Soluție: limita de iterații.

**Dependența de calitatea uneltelor**: dacă un API extern returnează date greșite, modelul va răspunde greșit.

## ReAct în practică: aplicații reale

- **Asistenți de cercetare**: caută informații, citează surse, sintetizează
- **Asistenți de codare**: scrie cod, testează, corectează pe baza output-ului
- **Automatizare business**: citește email, verifică baza de date, actualizează CRM
- **Asistent de cumpărături**: compară prețuri, verifică disponibilitate

## Concluzie

ReAct marchează tranziția de la modele AI care "știu" la modele AI care "acționează". Este fundamentul agenților AI moderni. Prin alternarea gândirii cu acțiunile și integrarea observațiilor din lumea reală, sistemele ReAct pot rezolva probleme care depășesc cu mult cunoașterea statică din training.
