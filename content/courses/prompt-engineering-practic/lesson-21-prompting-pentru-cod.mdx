# Prompting pentru Cod

AI-ul a schimbat fundamental felul în care scriem software. Nu mai vorbim doar despre autocompletare sau snippeturi — vorbim despre un partener de programare care poate genera funcții complete, depana erori, revizui cod și explica concepte tehnice. Diferența dintre un developer care folosește AI eficient și unul care nu îl folosește deloc este, în practică, echivalentul câtorva ore de muncă pe zi.

Dar calitatea output-ului depinde aproape integral de calitatea promptului. Un prompt vag primește cod vag. Un prompt precis primește cod utilizabil imediat.

## AI ca partener de programare

Înainte de a intra în tehnici specifice, e important să înțelegi ce rol ocupă AI-ul în fluxul tău de lucru. Nu este un motor de căutare pentru cod. Nu este Stack Overflow. Este mai aproape de un coleg senior care:

- Cunoaște multe limbaje și framework-uri
- Are răbdare infinită să explice
- Poate genera rapid variante multiple
- Nu știe contextul specific al proiectului tău — dacă nu i-l oferi tu

Această ultimă caracteristică este crucială. Cu cât mai mult context relevant oferi, cu atât mai util devine output-ul.

## Generarea de cod nou

Când ceri generarea de cod de la zero, specificitatea este totul. Gândește-te că formulezi un ticket de development, nu o cerere vagă.

**Ce să incluzi mereu:**
- Limbajul de programare și versiunea (Python 3.11, TypeScript 5, etc.)
- Semnătura funcției sau structura așteptată
- Cazuri limită pe care trebuie să le trateze
- Convențiile de cod dorite (type hints, docstrings, comentarii)
- Dependențe permise sau interzise

**Exemplu de prompt pentru generare de cod:**

```
Ești un senior Python developer. Scrie o funcție care primește o listă de email-uri și returnează doar cele valide (format user@domain.tld). Include type hints și docstring. Tratează cazul de input gol și cel de input care nu este o listă. Nu folosi biblioteci externe — doar re din standard library.
```

Observă că promptul specifică: rolul AI-ului, inputul funcției, outputul, formatul tehnic dorit (type hints, docstring), cazurile limită și o constrângere privind dependențele.

**Un alt exemplu — generare de endpoint REST:**

```
Ești un backend developer cu experiență în FastAPI. Scrie un endpoint POST /users/{user_id}/settings care: 1) validează că user_id este un UUID valid, 2) acceptă un body JSON cu câmpurile theme (light/dark) și notifications_enabled (bool), 3) returnează 422 pentru input invalid, 4) returnează 200 cu obiectul salvat la succes. Folosește Pydantic pentru validare. Adaugă type hints complete.
```

## Debugging: de la eroare la soluție

Debugging-ul este probabil cel mai frecvent caz de utilizare AI pentru developeri. Cheia este să oferi exact datele pe care le-ai oferi unui coleg senior care încearcă să reproducă problema.

**Ce să incluzi:**
- Mesajul de eroare exact (copy-paste, nu parafrazat)
- Codul relevant — nu tot proiectul, dar suficient pentru context
- Ce comportament așteptai versus ce s-a întâmplat
- Versiunile relevante (Python 3.9 vs 3.11 face diferența pentru unele erori)

**Exemplu de prompt pentru debugging:**

```
Primesc eroarea: TypeError: 'NoneType' object is not subscriptable la linia 23. Iată codul:

def get_user_config(user_id: str) -> dict:
    user = db.query(User).filter(User.id == user_id).first()
    return user.config["settings"]

Funcția este apelată cu un user_id valid. Explică de ce apare eroarea și oferă o soluție care tratează și cazul când user-ul nu există în bază de date.
```

Formularea "explică de ce apare" este importantă — vrei să înțelegi cauza, nu doar să primești un patch.

## Code Review: feedback specific, nu generic

Când ceri o revizuire de cod, specifică exact ce dimensiuni contează pentru tine. "Revizuiește acest cod" generează feedback generic și superficial.

**Exemplu de prompt pentru code review:**

```
Ești un senior code reviewer cu focus pe producție. Revizuiește acest cod JavaScript pentru: 1) bug-uri potențiale, inclusiv race conditions și edge cases, 2) probleme de performanță la volum mare, 3) vulnerabilități de securitate (XSS, injection), 4) lizibilitate și mentenabilitate. Pentru fiecare problemă găsită, oferă codul corectat. Marchează cu [CRITIC], [IMPORTANT] sau [MINOR] fiecare observație.

[codul tău aici]
```

Clasificarea cu [CRITIC]/[IMPORTANT]/[MINOR] te ajută să prioritizezi intervențiile.

## Refactoring: direcție clară, comportament păstrat

Refactoring-ul fără instrucțiuni clare duce la cod rescris după preferințele modelului, nu ale tale. Fii explicit despre ce vrei să se schimbe și ce trebuie să rămână identic.

**Exemplu de prompt pentru refactoring:**

```
Refactorizează această funcție pentru a fi mai lizibilă. Constrângeri: 1) păstrează exact același comportament și semnătură publică, 2) îmbunătățește denumirile variabilelor (în prezent sunt prescurtări criptice), 3) împarte logica în sub-funcții private dacă depășesc 15 linii, 4) adaugă comentarii doar unde logica nu este auto-explicativă. Nu schimba biblioteca de logging sau formatele de output.

[codul tău aici]
```

## Explicarea codului: pentru învățare și documentare

AI-ul excelează la explicarea codului complex. Util când preiei un proiect legacy, când înveți un nou framework sau când scrii documentație.

```
Explică ce face acest cod pas cu pas, ca și cum ai explica unui developer junior cu 6 luni experiență. Identifică pattern-urile de design utilizate și explică de ce autorul original ar fi ales această abordare față de alternative mai simple.

[codul tău aici]
```

## Scrierea de teste: cobertura gândită, nu aleatorie

Testele generate fără context nu acoperă cazurile limită importante. Oferă funcția, comportamentul așteptat și tipurile de teste dorite.

```
Scrie teste unitare pentru funcția de mai jos folosind pytest. Include: 1) cazul fericit (happy path), 2) input invalid (None, string gol, format greșit), 3) comportamentul la erori de rețea (mock pentru requests), 4) cazul de limită pentru numerele mari. Folosește pytest-mock pentru mocking. Adaugă docstring la fiecare test care explică ce verifică.

[funcția ta aici]
```

## Anti-pattern-uri frecvente

**"Scrie cel mai bun cod pentru X"** — "cel mai bun" este nedefinit. Cel mai rapid? Cel mai lizibil? Cel mai sigur? Specifică dimensiunea.

**Eroarea fără context** — "Am o eroare în Python, ce e greșit?" nu oferă suficiente informații. Mesajul exact și codul relevant sunt obligatorii.

**Ceea ce nu știe AI-ul** — AI-ul nu știe structura proiectului tău, convențiile interne ale echipei, sau variabilele de mediu configurate. Trebuie să furnizezi tu acest context.

**Acceptarea codului fără verificare** — Orice cod generat trebuie citit și înțeles înainte de a fi integrat. AI-ul poate genera cod plausibil dar incorect, mai ales pentru logică de business specifică sau integrări nefamiliare.

## Structura unui prompt ideal pentru cod

Un prompt bun pentru cod conține în general:

1. **Rolul** — "Ești un senior developer în [limbaj/framework]"
2. **Sarcina** — ce trebuie să facă codul
3. **Inputul/Outputul** — tipuri de date, formate
4. **Constrângeri** — dependențe, stilul de cod, performanță
5. **Cazuri limită** — ce trebuie tratat explicit
6. **Formatul răspunsului** — code + explicație? Doar code? Și teste?

## Concluzie

Prompting-ul pentru cod nu înseamnă să lași AI-ul să scrie în locul tău — înseamnă să colaborezi eficient cu un partener tehnic extrem de capabil. Cu cât mai precis definești problema, constrângerile și formatul dorit, cu atât mai utilizabil va fi output-ul primit. Investiția de 30 de secunde în a formula un prompt bun îți economisește minute sau ore de debuguit și rescris cod generic. Aplicați în mod constant, aceste tehnici pot transforma AI-ul dintr-un generator de snippeturi într-un multiplicator real al productivității tale.
