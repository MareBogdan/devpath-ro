# Formatarea Output-ului

Dacă fereastra de context determină **ce** știe modelul, formatarea output-ului determină **cum** primești răspunsul. Controlul explicit al formatului este una dintre cele mai practice și imediat aplicabile abilități din prompt engineering.

## De ce să controlezi formatul?

Implicit, modelele produc text liber — proze, paragrafe, explicații narative. Asta este adesea util, dar când construiești aplicații reale, ai nevoie de output structurat și predictibil:

- **Parsare automată**: codul tău trebuie să proceseze răspunsul
- **Consistență**: utilizatorii tăi se așteaptă la un format stabil
- **Downstream processing**: răspunsul alimentează un alt sistem (bază de date, API, UI)
- **Comparabilitate**: vrei să compari mai multe răspunsuri

## Formatele principale

### JSON

Cel mai util pentru aplicații. Permite parsare directă în orice limbaj de programare.

Prompt exemplu:

    Analizează recenzia următoare și returnează un JSON cu câmpurile:
    - sentiment: "pozitiv", "negativ", sau "neutru"
    - scor: număr de la 1 la 10
    - puncte_forte: array de string-uri (maxim 3)
    - puncte_slabe: array de string-uri (maxim 3)
    - rezumat: string de maxim 50 de cuvinte

    Recenzie: "Produsul e ok, am primit comanda în timp util, dar ambalajul
    era deteriorat și manualul lipsea. Serviciul clienți a răspuns rapid."

Răspuns așteptat:

    {
      "sentiment": "neutru",
      "scor": 6,
      "puncte_forte": ["livrare în timp", "suport client rapid"],
      "puncte_slabe": ["ambalaj deteriorat", "manual lipsă"],
      "rezumat": "Produsul a ajuns la timp, suportul a fost prompt,
                  dar ambalajul era stricat și lipsea documentația."
    }

### Markdown structurat

Util pentru documentație, rapoarte, conținut pentru web.

    Scrie un raport tehnic despre Python vs JavaScript pentru backend,
    folosind următoarea structură Markdown:
    # Titlu
    ## Introducere (2-3 propoziții)
    ## Comparație (tabel cu 5 criterii)
    ## Recomandare (1 paragraf)
    ## Concluzie (bullet points, maxim 4)

### Liste numerotate vs bullet points

Când vrei instrucțiuni pas-cu-pas, cere explicit:

    Explică cum să setezi un mediu virtual Python.
    Folosește pași numerotați. Fiecare pas are maxim 2 propoziții.
    Adaugă o notă de atenție (bold) la pașii care pot cauza probleme.

### Tabele

    Compară cele mai populare 5 baze de date NoSQL.
    Format: tabel Markdown cu coloanele: Nume, Tip, Use Case Principal,
    Limitare Principală, Popularitate (1-5 stele).

## Controlul lungimii

Modelele tind să fie verbose. Specificarea explicită a lungimii ajută enorm:

- "Răspunde în maxim 3 propoziții."
- "Rezumat de maxim 100 de cuvinte."
- "Fii concis. Fără introducere, direct la subiect."
- "Explică pe larg, minim 3 paragrafe cu exemple."

## Controlul stilului și tonului

    Reescrie textul următor pentru trei audiențe diferite:
    1. Versiunea pentru expert tehnic (jargon acceptat, concis)
    2. Versiunea pentru manager non-tehnic (fără jargon, focus pe business impact)
    3. Versiunea pentru utilizator final (limbaj simplu, focus pe beneficii)

    Text: [textul tău tehnic]

## Formate speciale pentru uz specific

### Extragerea datelor structurate

    Din textul următor, extrage toate persoanele menționate.
    Format: CSV cu coloanele: Nume, Rol, Organizație.
    Dacă o informație lipsește, scrie "N/A".
    Returnează doar CSV-ul, fără text suplimentar.

    Text: [articol de știri sau document]

### Generarea de cod cu documentare

    Scrie o funcție Python care [descriere].
    Cerințe de format:
    - Docstring conform Google style
    - Type hints pentru toți parametrii și return
    - Comentarii inline pentru logica complexă
    - Exemplu de utilizare în comentariul final

## Tehnici avansate de formatare

### Few-shot pentru format

Arată modelului exact formatul dorit prin exemple:

    Clasifică propoziția și returnează în formatul de mai jos.

    Input: "Vreau să cumpăr un laptop nou."
    Output: {"intentie": "cumparare", "produs": "laptop", "urgenta": "nespecificata"}

    Input: "Am nevoie urgent de un telefon până mâine."
    Output: {"intentie": "cumparare", "produs": "telefon", "urgenta": "ridicata"}

    Input: "Mă gândesc să schimb tastatura."
    Output:

### Schema explicită

    Returnează date în format JSON conform acestei scheme TypeScript:
    interface Produs {
      id: string;
      nume: string;
      pret: number;
      categorie: "hardware" | "software" | "servicii";
      disponibil: boolean;
      taguri: string[];
    }

## Erorile comune de formatare

**Problema**: Modelul adaugă text explicativ în jurul JSON-ului dorit.
**Soluție**: "Returnează DOAR JSON-ul, fără niciun text înainte sau după."

**Problema**: Formatarea este inconsistentă între apeluri.
**Soluție**: Oferă un exemplu concret de output dorit în prompt.

**Problema**: Modelul ignoră limitele de lungime.
**Soluție**: "Acesta este un criteriu strict. Dacă răspunsul depășește [X] cuvinte, trunchiați și adăugați [...]."

## Concluzie

Controlul formatării este, adesea, mai important decât conținutul pentru aplicațiile reale. Un răspuns perfect dar neparsabil este inutil. Investește timp în definirea precisă a formatului de output — economisești ore de debugging ulterior.

Principiul de bază: **dacă nu specifici formatul, modelul va alege el — și alegerea lui poate fi imprevizibilă de la un apel la altul**.
