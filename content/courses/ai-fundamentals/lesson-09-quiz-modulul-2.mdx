  - question: "Care este diferența esențială dintre Machine Learning și programarea clasică?"
    options:
      - "Machine Learning este mai rapid, programarea clasică este mai precisă"
      - "În ML modelul descoperă regulile din date; în programarea clasică tu scrii regulile explicit"
      - "Machine Learning poate fi folosit doar cu rețele neuronale mari"
      - "Programarea clasică necesită date etichetate, ML nu"
    correct: 1
    explanation: "Diferența fundamentală: în programarea clasică tu definești logica explicit (if/else, formule). În Machine Learning, tu furnizezi date + răspunsuri corecte, iar modelul descoperă singur regulile interne. Asta permite ML să rezolve probleme unde regulile sunt prea complexe pentru a fi scrise manual (recunoaștere imagini, NLP, etc.)."

  - question: "Ai un dataset de emailuri marcate ca 'spam' sau 'nu spam'. Ce tip de Machine Learning folosești?"
    options:
      - "Unsupervised Learning — pentru că emailurile pot fi grupate în categorii"
      - "Reinforcement Learning — modelul primește recompensă când clasifică corect"
      - "Supervised Learning — ai date etichetate și vrei să prezici eticheta pentru emailuri noi"
      - "Semi-supervised Learning — pentru că nu toate emailurile sunt etichetate"
    correct: 2
    explanation: "Supervised Learning înseamnă că antrenezi pe date ETICHETATE (spam/nu spam) și vrei să prezici eticheta pentru exemple noi. Avem datele de intrare (textul emailului) și eticheta corectă — definiția clasică a Supervised Learning. Clasificarea spam este, de fapt, unul dintre primele exemple istorice de Supervised ML."

  - question: "Ce măsoară 'Loss Function' într-un model de Machine Learning?"
    options:
      - "Câtă memorie RAM consumă modelul în timpul antrenării"
      - "Numărul de parametri din model — cu cât mai mulți, cu atât mai bun"
      - "Cât de departe sunt predicțiile modelului față de valorile corecte"
      - "Viteza de convergență a algoritmului de optimizare"
    correct: 2
    explanation: "Loss Function (funcția de pierdere) măsoară eroarea modelului — cât de greșite sunt predicțiile față de răspunsurile corecte. Scopul întregului proces de antrenare este minimizarea acestei valori. Cu cât loss-ul e mai mic, cu atât predicțiile sunt mai precise."

  - question: "Ai antrenat un model cu acuratețe 98% pe training set și 59% pe validation set. Ce problemă ai?"
    options:
      - "Underfitting — modelul e prea simplu și trebuie mărită complexitatea"
      - "Overfitting — modelul a memorat datele de antrenare și nu generalizează"
      - "Datele de validare sunt greșite și trebuie colectate din nou"
      - "Learning rate-ul este prea mic și antrenarea nu a conversat"
    correct: 1
    explanation: "Diferența uriașă (98% vs 59%) este semnalul clasic de OVERFITTING. Modelul a 'memorat' datele de antrenare inclusiv zgomotul și excepțiile, în loc să învețe pattern-urile generale. Soluții: dropout, early stopping, mai multe date de antrenare, sau reducerea complexității modelului."

  - question: "Ce este 'Early Stopping' și de ce se folosește?"
    options:
      - "O tehnică de oprire a antrenării după un număr fix de epoci pentru a economisi timp"
      - "O metodă de a opri antrenarea când validation loss crește, prevenind overfitting-ul"
      - "Un algoritm care oprește antrenarea dacă training loss ajunge la zero"
      - "O strategie de reducere a learning rate-ului în ultimele epoci de antrenare"
    correct: 1
    explanation: "Early Stopping monitorizează validation loss în timpul antrenării. Când validation loss începe să CREASCĂ (chiar dacă training loss continuă să scadă), știm că modelul a intrat în overfitting. Oprim antrenarea și salvăm versiunea cu cel mai mic validation loss. Este una dintre cele mai eficiente și simple tehnici anti-overfitting."
