## Overfitting și Underfitting

Aceasta este lecția care separă beginner-ii de practicienii reali în ML.

Poți să ai un model cu **99% acuratețe pe datele de antrenare** și totuși să fie **complet inutil în producție**. Cum? Prin **overfitting**.

Și poți să ai un model prea simplu care nu prinde niciun pattern — asta e **underfitting**.

Ambele sunt "boli" ale antrenării. Hai să le înțelegem și să vedem cum le tratăm.

### Underfitting — Modelul prea simplu

**Underfitting** apare când modelul e **prea simplu** pentru a capta complexitatea datelor.

```
Date reale: O curbă complexă, sinuoasă
Modelul:    O linie dreaptă

Rezultat: Modelul nu prinde niciun pattern real.
          Greșit atât pe training, cât și pe date noi.
```

**Cauze:**
- Model prea mic (prea puțini parametri)
- Prea puține epoci de antrenare
- Learning rate prea mare (sare peste minimum)

**Semnale de alarmă:**
```python
# Dacă vezi asta, ai underfitting:
Training accuracy:   55%   # Prost
Validation accuracy: 54%   # La fel de prost

# Modelul nu a învățat nimic semnificativ
```

---

### Overfitting — Modelul prea "bun" pe training

**Overfitting** apare când modelul **memorează datele de antrenare** în loc să învețe pattern-urile generale.

```
Date reale: O curbă moderată cu câteva anomalii
Modelul:    O curbă ultra-complexă care trece EXACT prin fiecare punct

Rezultat: Perfecte pe training, dezastruoase pe date noi.
          A memorat zgomotul, nu pattern-ul.
```

**Cauze:**
- Model prea complex (prea mulți parametri)
- Prea puține date de antrenare
- Prea multe epoci (modelul "memorează")
- Lipsă de regularizare

**Semnale de alarmă:**
```python
# Dacă vezi asta, ai overfitting:
Training accuracy:   99%   # Excelent... pe training
Validation accuracy: 61%   # Dezastruos pe date noi

# Diferența mare = semnal clar de overfitting
```

---

### Graficul clasic: Learning Curves

Când plotezi training accuracy și validation accuracy de-a lungul epocilor:

- **Underfitting:** ambele rămân joase
- **Zona ideală:** ambele sunt ridicate și apropiate
- **Overfitting:** training continuă să crească, validation stagnează sau scade

Diferența mare între cele două curbe este semnalul principal de alarmă.

---

### Soluții pentru Overfitting

**1. Mai multe date**
```python
# Cel mai eficient remediu — dar nu mereu posibil
# Dublez datele → overfitting scade semnificativ în mod tipic
```

**2. Data Augmentation**
```python
# Dacă nu poți colecta mai multe date, creează variații artificiale
from torchvision import transforms

augmentare = transforms.Compose([
    transforms.RandomHorizontalFlip(),      # Rotire orizontală
    transforms.RandomRotation(10),           # Rotire 10°
    transforms.ColorJitter(brightness=0.2), # Schimbă luminozitatea
])

# O singură poză de pisică → 50 de variații → modelul nu mai "memorează"
```

**3. Dropout**
```python
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(784, 256),
    nn.ReLU(),
    nn.Dropout(p=0.5),   # Dezactivează aleatoriu 50% din neuroni la fiecare pas
    nn.Linear(256, 10),
)
# Dropout forțează modelul să nu se "bazeze" pe niciun neuron specific
# → Generalizare mai bună
```

**4. Early Stopping**
```python
# Oprești antrenarea când validation loss CREȘTE (semn de overfitting)
best_val_loss = float('inf')
patience = 10  # Aștept 10 epoci fără îmbunătățire
epoci_fara_progres = 0

for epoca in range(1000):
    train_model(...)
    val_loss = evaluate(validation_data)

    if val_loss < best_val_loss:
        best_val_loss = val_loss
        salveaza_model()      # Salvez cel mai bun model
        epoci_fara_progres = 0
    else:
        epoci_fara_progres += 1
        if epoci_fara_progres >= patience:
            print(f"Early stopping la epoca {epoca}")
            break

incarca_cel_mai_bun_model()
```

**5. Regularizare L2**
```python
# Penalizează parametrii mari → model mai simplu, mai general
optimizer = torch.optim.Adam(model.parameters(),
                             weight_decay=1e-4)  # L2 regularization
```

### Bias-Variance Tradeoff

Overfitting și underfitting sunt două fețe ale aceleiași probleme fundamentale:

```
Eroare totală = Bias² + Variance + Noise ireductibil

Bias (Underfitting):
  Model face presupuneri prea simple.
  "Am presupus că prețul casei depinde doar de suprafață."

Variance (Overfitting):
  Model prea sensibil la datele de antrenare.
  "Am memorat prețul exact al fiecărei case din dataset."
```

**The Goldilocks Principle:**
- Prea mult Bias → Underfitting
- Prea multă Variance → Overfitting
- Just right → Generalizare bună 🎯

---

### Checklist practic

```
□ Împarte datele: 70% train / 15% val / 15% test
□ Monitorizează atât training loss, cât și validation loss
□ Dacă train loss ≈ val loss și ambele mari → UNDERFITTING
   → model mai mare, mai multe epoci
□ Dacă train loss << val loss → OVERFITTING
   → dropout, mai multe date, early stopping
□ Nu te uita niciodată la test set în timpul antrenării
□ Test set = "examenul final", îl folosești o singură dată
```

---

### Recapitulare

✅ **Underfitting** = model prea simplu, nu prinde pattern-urile → mărește modelul
✅ **Overfitting** = model memorează datele → dropout, early stopping, mai multe date
✅ **Semnalul clar:** diferența mare între training accuracy și validation accuracy
✅ **Bias-Variance tradeoff** = echilibrul fundamental al oricărui model ML
