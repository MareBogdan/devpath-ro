## Context Window — cât de mult "ține minte" un LLM

Ai trimis vreodată un document lung unui chatbot AI și ai observat că la un moment dat "uită" ce ai spus la început? Sau ai primit eroarea "context length exceeded"? Aceste comportamente au o explicație precisă: **Context Window**.

---

### Ce este Context Window

**Context Window** este numărul maxim de tokeni pe care modelul îi poate procesa simultan — input + output laolaltă.

```
Context Window = tot ce "vede" modelul la un moment dat:

┌─────────────────────────────────────────┐
│ CONTEXT WINDOW (ex: 128.000 tokeni)     │
│                                         │
│ System Prompt        ~500 tokeni        │
│ Conversation History ~50.000 tokeni     │
│ Document atașat      ~70.000 tokeni     │
│ User message curent  ~200 tokeni        │
│ ─────────────────────────────────────── │
│ TOTAL INPUT:         ~120.700 tokeni    │
│                                         │
│ Output (generat):    max ~7.300 tokeni  │
└─────────────────────────────────────────┘
```

### De ce Context Window e limitat — Complexitatea O(n²)

Limitarea nu e arbitrară. Self-Attention din Transformer are **complexitate pătratică**:

```python
def attention_complexity_analysis():
    """
    Self-Attention calculează similaritatea fiecărui token
    cu fiecare alt token din secvență.

    Dacă avem n tokeni: n × n = n² calcule de similaritate
    """

    sequence_lengths = [1_000, 10_000, 100_000, 1_000_000]

    for seq_len in sequence_lengths:
        comparisons = seq_len ** 2
        # Memoria necesară pentru matricea de atenție (float32 = 4 bytes)
        memory_gb = comparisons * 4 / 1e9
        print(f"{seq_len:>10,} tokeni → {comparisons:>15,} calcule → ~{memory_gb:.1f}GB memorie")

# Output:
#       1,000 tokeni →       1,000,000 calcule → ~0.0GB memorie
#      10,000 tokeni →     100,000,000 calcule → ~0.4GB memorie
#     100,000 tokeni →  10,000,000,000 calcule → ~40.0GB memorie
#   1,000,000 tokeni → 1,000,000,000,000 calcule → ~4000.0GB memorie

# Atingerea unui context window de 1M tokeni a necesitat inovații majore:
# Flash Attention, Ring Attention, Sliding Window Attention
```

### KV Cache — de ce generarea e rapidă

La generare, modelul nu recalculează atenția de la zero pentru fiecare token nou. Folosește **KV Cache** (Key-Value Cache):

```python
# Faza de PREFILL (procesare prompt):
# - Model procesează toți tokenii din prompt deodată
# - Calculează și STOCHEAZĂ K, V pentru fiecare token și layer
# - Operație relativ lentă (dar o dată!)

# Faza de DECODE (generare token cu token):
# - Pentru fiecare nou token generat:
#   → Calculează Q, K, V DOAR pentru noul token
#   → Recuperează K, V anterioare din CACHE
#   → Atenție față de toți tokenii precedenți (din cache)
#   → Adaugă noul K, V la cache
# - Operație rapidă!

# Vizualizare:
kv_cache_demo = """
Prompt: "Capitala Franței este"  (4 tokeni, prefill)
┌─────────────────────────────────────────────────────┐
│ KV Cache după prefill:                              │
│ Token 0 "Capitala" → K0=[...], V0=[...]            │
│ Token 1 "Franței"  → K1=[...], V1=[...]            │
│ Token 2 "este"     → K2=[...], V2=[...]            │
└─────────────────────────────────────────────────────┘

Generare Token 1:
- Model calculează: Q_new, K_new, V_new pentru "Paris"
- Atenție față de: K0, K1, K2, K_new (din cache + nou)
- Output: "Paris" cu probabilitate 0.87
- Adaugă K_new, V_new la cache

Generare Token 2:
- Recuperează K0..K_new din cache
- Calculează doar K, V pentru "," (virgulă)
- ...și tot așa
"""
```

### Flash Attention — eficiența memoriei

Flash Attention (2022, Tri Dao et al.) a revoluționat implementarea atenției:

```
Atenție clasică:
1. Calculezi întreaga matrice Q×K^T → salvezi în GPU HBM (memorie lentă)
2. Aplici softmax → citești/scrii în HBM
3. Înmulțești cu V → citești/scrii în HBM
Memorie: O(n²), multe accese lente la HBM

Flash Attention v2:
1. Procesezi atenția în BLOCURI care încap în SRAM (memorie rapidă on-chip)
2. Calculează softmax "online" — fără a materializa întreaga matrice
3. Scriere minimă în HBM
Memorie: O(n), viteza: 2-4x față de atenție clasică

Rezultat practic:
- Flash Attention a permis context windows de 100k+ tokeni să devină practice
- Aproape toate LLM-urile moderne îl folosesc
```

### Strategii pentru documente mai lungi decât contextul

```python
from typing import List

# Strategia 1: Sliding Window (Fereastră glisantă)
def sliding_window_process(text: str, chunk_size: int = 100_000,
                           overlap: int = 10_000) -> List[str]:
    """
    Procesezi bucăți suprapuse secvențial.
    Bun pentru: rezumare secvențială, extracție liniară.
    Problema: nu captezi relații de la început la final.
    """
    chunks = []
    for i in range(0, len(text), chunk_size - overlap):
        chunks.append(text[i:i + chunk_size])
    return chunks

# Strategia 2: RAG (Retrieval Augmented Generation)
# Stochezi chunks în vector DB, retrievi doar cele relevante pentru întrebare
# Bun pentru: Q&A pe documente mari
# DETALII COMPLETE ÎN LECȚIA 26

# Strategia 3: Map-Reduce
def map_reduce_summarize(document: str, model, chunk_size: int = 50_000) -> str:
    """
    Map:    rezumează fiecare chunk independent → N rezumate scurte
    Reduce: rezumează toate rezumatele → rezumat final
    Bun pentru: rezumarea cărților întregi
    """
    chunks = [document[i:i+chunk_size] for i in range(0, len(document), chunk_size)]

    # Map phase
    summaries = []
    for chunk in chunks:
        summary = model.summarize(chunk)  # ~500 tokeni fiecare
        summaries.append(summary)

    # Reduce phase
    combined = "\n\n".join(summaries)
    final_summary = model.summarize(combined)  # Rezumatul rezumatelor
    return final_summary
```

### Lost in the Middle — un fenomen real

Cercetătorii (Liu et al., 2023) au descoperit că LLM-urile nu folosesc uniform informația din context:

```
Performanța modelului în funcție de POZIȚIA informației relevante:

Scor
 ▲
 │  ██                              ██
 │ ████                            ████
 │██████                          ██████
 │████████░░░░░░░░░░░░░░░░░░░░░░░░████████
 └────────────────────────────────────────► Poziție în context
  ÎNCEPUT                             SFÂRȘIT
         ↑
    ZONA MOARTĂ: informația de la mijloc e mai puțin utilizată!

Implicație practică:
- Informația critică → la ÎNCEPUT sau SFÂRȘIT
- Evită să "îngropii" instrucțiunile importante la mijloc
- Tehnici: repetă instrucțiunile la final, folosește markeri vizibili
```

### Recapitulare

✅ **Context Window:** numărul maxim de tokeni procesați simultan (input + output)
✅ **Complexitate O(n²):** Self-Attention crește pătratic cu lungimea contextului
✅ **KV Cache:** stochează K și V pentru tokenii precedenți → generare rapidă token-by-token
✅ **Flash Attention:** implementare eficientă care reduce memoria la O(n)
✅ **Lost in the Middle:** informația din mijlocul contextului e mai puțin utilizată
