## Arhitectura Transformer — Atenția care a revoluționat AI-ul

În 2017, opt cercetători Google au publicat un paper cu titlul "Attention is All You Need". Era o afirmație îndrăzneață — și s-a dovedit complet corectă. Transformers sunt astăzi fundația tuturor modelelor moderne: GPT-4, Claude, Gemini, Llama, Mistral, toate.

Această lecție îți explică **de ce** Transformers au câștigat și **cum** funcționează atenția.

---

### Problema pe care o rezolvă Transformers

Înainte de Transformers, modelele dominante erau RNN-urile și LSTM-urile. Aveau o limitare fundamentală:

**Procesare secvențială:** cuvânt 1 → cuvânt 2 → cuvânt 3 → ... → cuvânt N

```
Propoziție: "Băiatul care a câștigat olimpiada națională de fizică este genial"

RNN trebuie să proceseze 10 cuvinte în secvență.
La cuvântul 10 ("genial"), informația despre "Băiatul" (cuvântul 1)
s-a diluat prin 9 pași de calcul.
```

**Două probleme:**
1. **Gradient vanishing:** informația din trecut se "uită" la secvențe lungi
2. **Nu se poate paraleliza:** nu poți procesa cuvântul 5 fără să fi terminat cu 1-4

Transformers rezolvă ambele prin **Self-Attention**: fiecare cuvânt "privește" direct la toate celelalte cuvinte simultan.

---

### Self-Attention — Inima Transformer-ului

Self-Attention calculează pentru fiecare token **cât de relevante sunt toate celelalte tokeni** față de el.

**Conceptual:**

```
Propoziție: "The bank can guarantee deposits will eventually cover future losses"

Când procesăm cuvântul "bank":
  → "bank" (cuvântul curent) — atenție mare (e el însuși)
  → "deposits"              — atenție mare (context financiar, nu malul râului!)
  → "guarantee"             — atenție medie
  → "losses"                — atenție medie
  → "The"                   — atenție mică (articol neimportant)
```

Modelul **înțelege din context** că "bank" = bancă, nu mal de râu.

**Mecanismul Q/K/V:**

Self-Attention folosește trei matrice: **Query (Q)**, **Key (K)**, **Value (V)**.

```python
import numpy as np

def self_attention(Q, K, V):
    """
    Q: Query matrix  — "ce caut?"
    K: Key matrix    — "ce ofer ca index?"
    V: Value matrix  — "ce informație transport?"
    d_k: dimensiunea key-ului (pentru scalare)
    """
    d_k = Q.shape[-1]

    # 1. Calculăm scorurile de similaritate (dot product)
    scores = np.matmul(Q, K.transpose(-2, -1)) / np.sqrt(d_k)

    # 2. Softmax → probabilități (suma = 1 pe fiecare rând)
    attn_weights = np.exp(scores) / np.sum(np.exp(scores), axis=-1, keepdims=True)

    # 3. Înmulțim cu Value → output
    output = np.matmul(attn_weights, V)

    return output, attn_weights

# Exemplu minimal:
# Secvență de 3 tokeni, dimensiune embedding = 4
seq_len, d_model = 3, 4
Q = np.random.randn(seq_len, d_model)
K = np.random.randn(seq_len, d_model)
V = np.random.randn(seq_len, d_model)

output, weights = self_attention(Q, K, V)
print(f"Output shape: {output.shape}")   # (3, 4)
print(f"Attention weights:\n{weights}")  # 3x3 matrix, fiecare rând sumează la 1
```

**Intuiție:**
- Q = întrebarea pe care o pune fiecare token ("ce context am nevoie?")
- K = "cartea de vizită" a fiecărui token ("iată ce ofer")
- V = informația efectivă pe care o transmite tokenul
- Scorurile = potrivire Q×K → câtă atenție acordi
- Output = sumă ponderată a V-urilor

### Multi-Head Attention

În loc de o singură atenție, Transformers folosesc **mai multe capete de atenție în paralel**:

```python
def multi_head_attention(x, num_heads=8, d_model=512):
    """
    Fiecare cap de atenție se specializează pe un tip diferit de relație:
    - Capul 1: poate urmări subiectul gramatical
    - Capul 2: poate urmări referințele pronominale
    - Capul 3: poate urmări relațiile semantice
    - ...
    """
    d_k = d_model // num_heads  # 512/8 = 64 pe cap

    heads = []
    for i in range(num_heads):
        # Fiecare cap are propriile matrice Q, K, V (proiecții liniare)
        Q_i = np.matmul(x, np.random.randn(d_model, d_k))
        K_i = np.matmul(x, np.random.randn(d_model, d_k))
        V_i = np.matmul(x, np.random.randn(d_model, d_k))

        head_i, _ = self_attention(Q_i, K_i, V_i)
        heads.append(head_i)

    # Concatenăm toate capetele → (seq_len, d_model)
    concatenated = np.concatenate(heads, axis=-1)
    return concatenated
```

### Positional Encoding

Self-Attention e "bag of words" din punct de vedere al ordinii — nu știe că "câinele mușcă omul" ≠ "omul mușcă câinele". Soluția: **Positional Encoding** adaugă informații despre poziție la fiecare token.

```python
def positional_encoding(seq_len, d_model):
    """
    Folosim funcții sin/cos la frecvențe diferite.
    Proprietate importantă: PE(pos+k) poate fi calculat din PE(pos)
    → modelul poate extrapola la secvențe mai lungi decât cele din antrenare
    """
    PE = np.zeros((seq_len, d_model))

    for pos in range(seq_len):
        for i in range(0, d_model, 2):
            PE[pos, i]   = np.sin(pos / (10000 ** (2*i / d_model)))
            PE[pos, i+1] = np.cos(pos / (10000 ** (2*i / d_model)))

    return PE
```

### Arhitectura completă: Encoder vs Decoder

Paper-ul original definea două componente:

**Encoder** (BERT, DistilBERT):
```
Input tokens → Embeddings + PE
     → [Self-Attention → Add&Norm → FFN → Add&Norm] × N layers
     → Reprezentări contextuale (utile pentru clasificare, NER, etc.)
```

**Decoder** (GPT, Llama):
```
Input tokens → Embeddings + PE
     → [Masked Self-Attention → Add&Norm → FFN → Add&Norm] × N layers
     → Predicție token următor
```

*Masked* self-attention: la antrenare, tokenul de la poziția t vede doar pozițiile 0..t-1, nu și viitorul.

**Encoder-Decoder** (T5, BART):
- Encoder procesează input-ul
- Decoder generează output-ul, folosind și reprezentările encoder-ului

### De ce Transformers au câștigat

| Caracteristică | RNN/LSTM | Transformer |
|---|---|---|
| Paralelizare | ❌ Secvențial | ✅ Complet paralel |
| Dependențe lungi | ⚠️ Slabe | ✅ Directe (O(1) pași) |
| Scalabilitate GPU | ❌ Slabă | ✅ Excelentă |
| Context maxim | ~1000 tokeni | 8k → 2M tokeni |
| Complexitate atenție | O(n) | O(n²) dar paralelizabil |

### Recapitulare

✅ **Self-Attention:** fiecare token "privește" direct la toți ceilalți tokeni simultan
✅ **Q/K/V:** Query (ce caut), Key (ce ofer), Value (ce informație transport)
✅ **Multi-Head Attention:** mai multe capete paralele, fiecare captează relații diferite
✅ **Positional Encoding:** adaugă informații de ordine (sin/cos) la embeddings
✅ **Encoder vs Decoder:** BERT = encoder (înțelegere), GPT = decoder (generare)
